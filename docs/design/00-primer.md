本卷假定读者**没有 AI 背景**。九个概念只讲到「足够看懂对应设计决策」为止，不求系统全面。每张卡固定三段：**这是什么**（直觉解释）→ **在本项目里扮演什么角色** → **关联哪条设计决策**。读正文遇到不认识的 AI 术语，回到本卷对照即可。

## 1. Embedding：文本向量化

- **这是什么**：把一段文本送进模型，输出一串固定长度的浮点数（叫"向量"）。语义相近的文本，输出的数字串也相近。可以理解为"把一句话的**意思**翻译成一组坐标"。
- **在本项目里扮演什么角色**：语义缓存的**可行性根基**。有了它，才能对"换个说法问的同一个问题"做相似度比较，而不是死抠字符串是否完全相等（精确匹配）。
- **关联设计决策**：架构 §3.1（先精确匹配、未命中再 embedding）、§4.2（第 0 步如何免掉 embedding）、§4.6。

## 2. 向量相似度与距离方向

- **这是什么**：衡量两串数字有多像。最常用**余弦相似度**（看两个向量的夹角，1 = 方向完全一致、0 = 无关），也有用**欧氏距离**的（越小越近）。关键区别：**相似度越大越像，距离越小越近，两个方向相反**。
- **在本项目里扮演什么角色**：命中判定本质上就是"相似度 ≥ 阈值"。但底层库（hnswlib / BruteForce）用的是距离，所以必须在适配层换算成相似度，否则阈值会失灵。
- **关联设计决策**：§4.6。

## 3. 归一化（L2）与向量维度 dim

- **这是什么**：**归一化** = 把向量长度缩放到 1，只保留方向（丢弃"长短"）。**维度 dim** = 向量里数字的个数（例如 384、768），由所选模型决定。
- **在本项目里扮演什么角色**：归一化后，余弦相似度与欧氏距离可以互相换算，适配层只需处理一套口径；dim 决定向量索引与持久化元数据是否匹配。
- **关联设计决策**：架构 §3.3、roadmap 阶段 2。

## 4. ANN 近似最近邻：暴力搜索 vs HNSW

- **这是什么**：在一个 query 向量和成千上万条已存向量之间找最相似的几条，叫"最近邻搜索"。**暴力法**把所有向量两两比一遍（准，但慢）；**ANN** 用图结构（HNSW 是一种）走捷径（快，但可能漏掉个别最优解）。
- **在本项目里扮演什么角色**：规模小用 `BruteForceIndex`（阶段 1，零依赖、易测）；规模大换 `HnswIndex`（阶段 2）。`M` / `efConstruction` / `efSearch` 是它的精度—速度旋钮。
- **关联设计决策**：架构 §3.3、roadmap 阶段 2。

## 5. Embedding 模型生态

- **这是什么**：真正产向量的是**预训练模型**（本项目中文场景用 bge-small-zh-v1.5 一类）。典型流程：分词（tokenizer）→ 送进模型推理（ONNX Runtime 或 llama.cpp）→ 把每个 token 的输出平均（mean pooling）→ 归一化，得到整句话的向量。
- **在本项目里扮演什么角色**：阶段 2 把测试用的 `HashEmbedder` 换成真实模型；`HashEmbedder` 只生成确定性的**假向量**，专门用来测编排逻辑，不代表语义质量。它的实现（字节 n-gram 特征哈希 + FNV-1a + L2 归一化）见 [HashEmbedder 实现与算法详解](../HashEmbedder实现与算法详解.md)。
- **关联设计决策**：架构 §3.3、roadmap 阶段 2。

## 6. 模型指纹 modelId

- **这是什么**：不同模型 / 版本产出的向量处在不同的"坐标系"里，同一句话在 A 模型的向量和 B 模型的向量**没法直接比相似度**。`modelId` 就是给这个向量空间打的标签。
- **在本项目里扮演什么角色**：持久化索引加载时必须校验它；指纹不匹配就拒绝加载，否则算出来的相似度全是无意义的。
- **关联设计决策**：§4.2、roadmap 阶段 2。

## 7. 阈值与精确率 / 召回率

- **这是什么**：**阈值** = 判定"算不算同一个问题"的分数线。**精确率** = 被判成命中的里有多少是真的该命中（防误报）；**召回率** = 真正该命中的里有多少被找出来（防漏报）。阈值调高→精确率升、召回率降；调低反之。
- **在本项目里扮演什么角色**：§4.5 的核心论点——阈值是一条 P/R 曲线上的**操作点**，不是常量；应靠 benchmark 测出来，而不是拍脑袋。
- **关联设计决策**：§4.5、roadmap 阶段 3。

## 8. 语义缓存整体图景与 GPTCache 对照

- **这是什么**：LLM 调用又贵又慢，而很多用户问题只是**说法不同**。语义缓存 = 把历史 (问题 → 回答) 存起来，新问题先查有没有"意思一样"的旧问题，命中就直接返回旧回答、跳过 LLM 调用。
- **在本项目里扮演什么角色**：这就是整个项目的全貌。与 GPTCache 等开源方案的差异在于：淘汰决策复用成熟缓存策略、把**一致性（幽灵命中治理）**做成体系，以及给出可评测的阈值策略。
- **关联设计决策**：全文，尤其架构 §3、§4.1。

## 9. Benchmark 数据集：LCQMC / ATEC

- **这是什么**：中文**同义句配对**数据集，每条样本是"两句话 + 是否同义"。用来离线测一个模型 / 阈值判定得准不准。
- **在本项目里扮演什么角色**：阶段 3 测"阈值 → 精确率 / 召回率曲线"的数据来源。
- **关联设计决策**：roadmap 阶段 3。
